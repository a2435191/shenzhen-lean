    inductive IOEffects (ξ : Type u) (ι : Type v) (α : Type x) :
    Type (max (max u v) x)

    IOEffects ξ ι α represents a value of type α, possibly delayed until sleep, or reads/writes/peeks from XBus pins happen. We also record reads and writes from simple I/O pins, although they don't block.

    • ξ is the type of XBus pins.
    • ι is the type of simple I/O pins.
    • pure {ξ : Type u} {ι : Type v} {α : Type x} (a : α) : IOEffects ξ ι α

      Just return a value immediately, without doing any effects.

    • xBusRead {ξ : Type u} {ι : Type v} {α : Type x} (pin : ξ) (next : Integer → IOEffects ξ ι α) : IOEffects ξ ι α

      xBusRead pin next represents a computation delayed until a value d from pin can be read; then next d is the result of the computation.

    • xBusWrite {ξ : Type u} {ι : Type v} {α : Type x} (outPin : ξ) (d : Integer) (next : Unit → IOEffects ξ ι α) : IOEffects ξ ι α

      d is some data to be thereafter written out of outPin, and next () is returned after the write.

    • xBusPoll {ξ : Type u} {ι : Type v} {α : Type x} (pin : ξ) (next : Unit → IOEffects ξ ι α) : IOEffects ξ ι α

      xBusPoll pin next represents a computation delayed until the value from XBus pin pin arrives (but without consuming the value); then next () is the result thereafter. This is used to implement the slx instruction.

    • simpleIORead {ξ : Type u} {ι : Type v} {α : Type x} (pin : ι) (next : SimpleIOData → IOEffects ξ ι α) : IOEffects ξ ι α
    • simpleIOWrite {ξ : Type u} {ι : Type v} {α : Type x} (outPin : ι) (d : SimpleIOData) (next : Unit → IOEffects ξ ι α) : IOEffects ξ ι α
    • sleep {ξ : Type u} {ι : Type v} {α : Type x} (n : Nat) (h : n ≠ 0) (next : Unit → IOEffects ξ ι α) : IOEffects ξ ι α

      Wait for n time units.
